## Cambios principales

- Se construyó el onion model identificando los distintos niveles del sistema.
- Se elaboró el organigrama de los actores involucrados.
- Se registró la reunión inicial mediante una minuta de presentación de visión.

## Decisiones tomadas

- Utilizar el onion model como herramienta para organizar y comprender el dominio.
- Documentar los artefactos en formato Markdown para mantener consistencia en el repositorio.
- Registrar las reuniones clave mediante minutas para asegurar trazabilidad de decisiones.

## Riesgos y pendientes

- Falta de identificación completa de stakeholders negativos.
- Posible falta de alineación en las expectativas de los interesados.
- Información de reglas de negocio aún incompleta.

## Próximos pasos

- Encontrar stakeholders negativos.
- Realizar entrevistas con los interesados para profundizar en sus expectativas.
- Identificar posibles riesgos relacionados con los interesados negativos.
- Definir modulo inicial a desarrollar.
- Encontrar mas stakeholders que se beneficien con el sistema.
- Consultar reglas de negocio.
- Definir usuarios finales del sistema.
- Realizar historia de dominio, especificacion de requisitos, historia de usuarios y escenarios y matriz de trazabilidad.
